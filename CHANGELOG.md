## [Unreleased]

### Added

- **`cg update check` — binary update discovery (first slice of the auto-update subsystem).** Reports whether a newer `cg` release is available by querying the public GitHub Releases API anonymously (no `gh` or auth token required) and comparing the latest tag to the running version with proper semver ordering. Development builds (`dev`, dirty `git describe`) are detected and skip the check. A failed check (offline, GitHub unreachable) prints a notice and exits zero — it never fails the command. Discovery, semver comparison, and state-file paths live in a new pure, unit-tested `internal/autoupdate` package; the GitHub API base URL and target repo are overridable via `CONSIGLIERE_GITHUB_API_BASE` / `CONSIGLIERE_AUTO_UPDATE_REPO`. Groundwork for `cg update upgrade` (in-place self-replace) and the background freshness check in follow-up PRs.
- **`cg update upgrade` — in-place self-replace.** Downloads the platform release archive from GitHub, verifies its SHA-256 against the release `checksums.txt` (same artifact `install.sh` uses), extracts the `cg` binary, and atomically replaces the running executable via `minio/selfupdate` (rolls back on any failure, so a botched download never leaves a broken binary). **Homebrew and other non-`install.sh` installs are never self-replaced** — `cg` detects how it was installed (via `installed.json`'s `method`, falling back to a Homebrew-prefix path check) and points the user at `brew upgrade --cask cg` or the installer one-liner instead, so it can't corrupt a package manager's bookkeeping. Asset downloads honor `CONSIGLIERE_GITHUB_DOWNLOAD_BASE` for testing/forks.
- **Background update check.** On each meaningful `cg` run, a detached background worker checks GitHub for a newer release at most once every 24h (debounced) and, for `install.sh`-managed installs, auto-installs it; the next `cg` run prints a one-line `✅ cg updated to vX` notice. The worker is fully detached (own session, stdio closed) and self-throttled by a pidfile lock with stale-takeover, so it never blocks or breaks the user's command — all failures are swallowed to an `autoupdate.log`. Opt out with `--no-auto-update` (this run), `CONSIGLIERE_AUTO_UPDATE=0` (disable the worker), or `CONSIGLIERE_NO_UPDATE_NOTICE=1` (silence notices). The background check is skipped for dev builds and for the `version`/`help`/`update` commands. State lives under `${XDG_CONFIG_HOME:-$HOME/.config}/consigliere/`.
- **Major-version gate.** The background worker **never auto-installs a major (breaking) release** — instead it records a marker and every subsequent `cg` run shows a persistent, warn-only two-line notice pointing at the changelog. Minor/patch releases still auto-install. Resolve the notice with `cg update upgrade` (installs the latest with explicit consent), `cg update snooze --major` (silence for 7 days), or `cg update ignore --major` (permanently dismiss until a *newer* major appears). The marker auto-clears once the installed version reaches or passes the flagged major.

## [1.1.0] - 2026-06-11

### Added

- **Load-on-demand pattern + the first framework note (`claude-md-hygiene`).** `cg init` now ships `notes/claude-md-hygiene.md` — the extract-vs-inline discipline for editing CLAUDE.md — as a managed artifact (copied into the workspace and registered in `.cg/manifest.json`, so `cg sync` keeps it current). A new `cg:section:claude-md-hygiene` block in the embedded workspace `CLAUDE.md` is the pointer-style rule that loads the note on demand: a short trigger + the every-session-vs-trigger-only test + the note path, instead of inlining the full procedure. This establishes the load-on-demand convention the framework's larger rules will be refactored onto (one section per follow-up PR), keeping the always-loaded prompt lean. First exercise of the framework-notes machinery shipped in the workspace-sync foundation (the embed `notes/` tree was empty until now).
- **`/cg-sync` skill — the judgment half of workspace sync.** `cg init` now installs a `/cg-sync` Claude Code slash command alongside `/cg-init` and `/match-project`. It runs `cg sync`, then does what the deterministic command can't (workspace-sync DEC-004): reviews the incoming framework rules against the user's own `user:section` rules for **semantic contradictions**, surfaces each conflict with a recommendation before applying, runs `cg sync --apply` for the safe changes, and walks the user through each drifted artifact (keep-mine / take-theirs / reconcile) — reminding them that moving an override into a `user:section` makes it survive future syncs.
- **`cg sync` — workspace content reconciliation.** New command that classifies every framework-managed artifact (CLAUDE.md `cg:section` blocks and framework notes) by comparing three content hashes: what's on disk, what the manifest recorded `cg` last wrote, and what the current binary ships. Each artifact is labelled **up-to-date**, **updatable** (untouched by the user, framework changed — safe to auto-apply), **drifted** (user-edited — never clobbered), **new**, **removed**, or **missing**. Without flags `cg sync` is a dry run that prints a grouped report and writes nothing. With **`--apply`** it updates the untouched framework sections (in place, preserving sentinels) and notes (whole-file), inserts new ones, updates the manifest hashes for what it wrote, and bumps the recorded framework version — but **never touches a drifted (user-edited) artifact**; those are reported for the user (or the `/cg-sync` skill) to resolve. Apply is idempotent: a second run finds everything up to date. The deterministic classifier lives in a new pure, fully-unit-tested `internal/sync` package; `manifest` gained `ReplaceSection`/`AppendSection` for in-place section editing. A round-trip test exercises the full vN→vN+1 upgrade (changed/new/drifted sections and notes). Workspace-sync DEC-004/DEC-005.
- **Workspace-sync manifest foundation.** `cg init` now writes `.cg/manifest.json` recording every framework-managed `CLAUDE.md` section (by sentinel id) with a SHA-256 content hash, plus the framework version. This is durable, committed workspace state (not gitignored) that a future `cg sync` will use to upgrade workspace *content* in place — auto-updating untouched framework sections, never clobbering ones the user edited. A new internal `manifest` package parses `cg:section` blocks (ignoring user-owned `user:section` blocks) and reads/writes the manifest. The two-zone ownership contract and the `cg sync` (content) vs `cg update` (binary) boundary are documented in `docs/workspace-sync.md`. Existing workspaces are unaffected until re-initialized or synced; `notes` tracking is seeded empty and populated by the load-on-demand work.
- **Workspace-sync manifest now tracks framework notes.** `cg init` copies every framework note shipped under the embed tree's `notes/` directory into the workspace's `notes/` (skip-if-exists, like `CLAUDE.md`) and registers each in `.cg/manifest.json` under `notes` with a SHA-256 content hash, keyed by portable forward-slash workspace-relative path. The copied set mirrors the registered set exactly, so every manifest note record has a backing file on disk. A new `manifest.NotesFromFS` walks a notes tree and hashes each file, skipping directories and dotfiles — so the `.gitkeep` that keeps the otherwise-empty framework-notes directory present in the embed tree is never registered or copied. No user-facing change yet: the framework ships no notes today, so `notes` stays `{}` until the load-on-demand work populates the embed tree, at which point the records light up with no further `cg init` changes.
- `cg init --wizard` / `-i` — interactive setup walkthrough built on `charmbracelet/huh`. Collects name/role/responsibilities (written into `PROFILE.md`), an optional first area (slug, name, tags, overview — written to `areas/<slug>.md` and linked from `areas/INDEX.md`), and confirms `git init` + slash-command install. TTY-only; errors cleanly when stdin isn't a terminal. Non-interactive `cg init` behavior is unchanged.
- `cg --version` / `cg -v` root flags — identical output to `cg version` (`cg version <semver>`). The existing `cg version` subcommand is unchanged.
- **Pull Request Review Loop** rule shipped in the embedded workspace `CLAUDE.md` (new section `pr-review-loop`, delimited by `<!-- cg:section:start=pr-review-loop -->` / `<!-- cg:section:end=pr-review-loop -->`). Defines the post-`gh pr create` autoloop: fetch CI + inline + issue + review comments; for each comment either fix in a follow-up commit, reply with reasoning, or escalate to the user; re-run the fetch after each push; exit when all CI is green and every comment has been addressed. Explicitly prohibits silent resolution, amending review-branch commits, and dismissing bot reviews by default. Covers both human and bot reviewers (CodeRabbit, Copilot, dependabot).

The `cg:section:area-rules` block is now a pointer: the "every item needs an `Areas:` field / read the area first" headline inline, the detail behind the note. Pure relocation — no behaviour change. Completes the load-on-demand track: six framework rules now load on demand, with `claude-md-hygiene` as the seventh note.
- **`pr-review-loop` section refactored to load-on-demand (PR6 of the load-on-demand track).** The fetch probes, the per-comment fix/reply/escalate taxonomy, the CI-failure handling, the guardrails, and the session-end `/schedule` handoff moved out of the always-loaded workspace `CLAUDE.md` into a new framework note `notes/after-pr-checks.md` (a managed artifact). The `cg:section:pr-review-loop` block is now a pointer: the "MUST enter the loop" rule + the bot/silent-dismissal headline inline, the procedure + guardrails behind the note. - **`session-end` section refactored to load-on-demand (PR5 of the load-on-demand track).** The two step-by-step session-end capture procedures — Notes (category + tags + INDEX) and Insights (drafts) — moved out of the always-loaded workspace `CLAUDE.md` into a new framework note `notes/session-end-capture.md` (a managed artifact). Pure relocation — no behaviour change — trimming the always-loaded prompt by ~20 lines.

The `cg:section:idea-workflow` block is now a pointer: a one-line trigger inline, the lifecycle + status detail behind the note. Pure relocation — no behaviour change.
- **`information-propagation` section refactored to load-on-demand (PR3 of the load-on-demand track).** The trigger list, the step-by-step propagation procedure, and the new-information-type → what-to-update lookup table moved out of the always-loaded workspace `CLAUDE.md` into a new framework note `notes/information-propagation.md` (a managed artifact). The `cg:section:information-propagation` block is now a pointer: the trigger summary + the "this is not optional" headline inline, the detail behind the note. Pure relocation — no behaviour change — trimming the always-loaded prompt by ~30 lines.
- **`project-structure` section refactored to load-on-demand (PR2 of the load-on-demand track).** The full Project Structure mechanics — the standard/optional file tables, the rules for working with project files, the new-project workflow, and the per-session update checklist — moved out of the always-loaded workspace `CLAUDE.md` into a new framework note `notes/project-structure.md` (a managed artifact, like `claude-md-hygiene`). The `cg:section:project-structure` block is now a pointer: the one-line folder/four-files overview plus the two load-bearing every-session rules (read `README.md` first; keep files current) inline, with the detail behind the note. Pure relocation — no behaviour change — trimming the always-loaded prompt by ~45 lines.
- **Workspace CLAUDE.md template — two-zone ownership split finalized.** The embedded workspace `CLAUDE.md` now has zero orphan content between zones (workspace-sync DEC-002): the framework intro paragraph is wrapped in a new `cg:section:start=intro` block so `cg sync` keeps the contract description current, and the dead `<!-- cg:version=1.0.0 -->` marker was removed — no Go code read it, and the framework version is now owned authoritatively by `.cg/manifest.json` (`frameworkVersion`) and `.cg.json` (workspace-sync DEC-003). A new test (`TestEmbeddedCLAUDEHasNoOrphanContent`) enforces the contract: every non-blank line outside the H1 title must sit inside a `cg:section` or `user:section` block, with no nested or unclosed zones.
- **Area taxonomy: free-form tags replace category enum.** Area files now carry a `Tags:` field (comma-separated, multi-valued, normalized to lowercase) instead of a binary `Category: Service/System | Practice/Platform` choice. `areas/INDEX.md` is now a single flat table with a Tags column instead of two category-split tables. Rationale: the category split forced blurry areas into arbitrary buckets, read enterprise-flavored (poor fit for personal-project workspaces), and was inconsistent with how ideas already use free-form tags. The wizard's category-select step is replaced by a free-text tag input. Existing workspaces need a manual migration (add `Tags:` lines to area frontmatter; flatten `areas/INDEX.md`) since there is no automated migrator in this release.

### Migration

- **Existing workspaces pick up the seven framework notes and the slimmed `CLAUDE.md` sections by running `cg sync --apply`** (or the `/cg-sync` skill). Because the notes ship as managed artifacts and the refactors are pure relocations, `cg sync` auto-applies the new notes plus every framework section you haven't hand-edited; any section you *have* edited is reported as **drifted** and left untouched for you to reconcile (keep-mine / take-theirs / move your override into a `user:section` so it survives future syncs). No content is lost — the relocated rules are identical, just loaded on demand. Re-running `cg init` in a fresh workspace gets the new layout directly.
